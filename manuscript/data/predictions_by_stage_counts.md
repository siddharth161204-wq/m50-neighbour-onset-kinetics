While this table was being built, commit 0528d8b (12:36 UTC, 2 November 2026) added `results/stage11_scorecard.json`, which records P1 failed, P2 held, P3 held, P4 failed, P5 failed and P6 failed. The README has no Stage 11 scorecard yet, so these verdicts are not cross-checked here and are not entered in the CSV.

"Foreseen" counts failed predictions only. A failure is marked "yes" when, before the runs, the predictions file stated that the failure followed from earlier stages' records, the study's pre-run estimates or an energy balance: its study expectation was "Fails" or "expected to fail", or it said the failure was fixed, or it named a condition for the failure that then held. A hedged "may fail" does not count, nor does a condition named for a prediction to hold. Held predictions and Stage 11 rows leave the column empty.

- Counting the three "may fail" expectations as foreseen too (Stage 4 P4, Stage 5 P1 and P6) would give 24 (note 4).

## Ambiguities

1. **Stage 3 P3 and P6 (marked yes).** The study's central estimates say `"expected to fail on both counts"` (predictions_stage3.md:27) and `"36.5 %: expected to fail"` (predictions_stage3.md:30). They rest on the study's own pre-run estimate, `"So each draw's onset is estimated as the first time each archived history reaches the temperature at which that draw starts on the matching synthetic ramp."` (predictions_stage3.md:61). The README (lines 148 and 151, e.g. `"Failed on both counts"`) and the note (lines 47 and 50) never call these failures foreseeable. Without them the total is 19.
2. **Stage 6 P4 (marked yes, on the energy balance).** The predictions file says `"107.0 kJ released in cell 1 (61.75 J/K) would raise it 1,733 K adiabatically"` and `"so the total is expected not to qualify"` (predictions_stage6.md:19), with `"Estimated by hand only: near 1,500 to 1,600 C."` (line 39) and the study expectation "Fails.". The README tags only five failures `"Failed (foreseeable)"`, says `"five of the seven verdicts were foreseeable"` (README.md:349), and defines the tag as `"Stage 5's published records already fixed or nearly fixed these outcomes"` (README.md:392). The note agrees: `"five of them foreseeable from Stage 5's records"` (note line 77). By that definition, records only, P4 is not foreseeable; by this table's definition, records or an energy balance, it is.
3. **Stage 9 P6 (marked yes, on a condition the file named).** The file says `"Uncertain; fails if M50_PT_Exp4 has no f_t."` (predictions_stage9.md:45). The README says `"P3 and P6 were uncertain there"` and `"P6 failed, as it would if M50_PT_Exp4 had no f_t(C1) under 240 s"` (README.md:613), while the note says P4, P5 and P6 `"failed, each as its predictions expected"` (note line 108). The README and the note therefore disagree on whether P6 was expected. P6 also failed on M50_PP_Exp2, which the file did not foresee: it estimated `"The sizing estimate puts f_t(C1) near 0.26 for M50_PP_Exp2"` (line 45), and the README records `"in M50_PP_Exp2 no fraction reproduces the time, its bracket (0.05, 0.053125] straddling a jump"` (README.md:613).
4. **"May fail" (marked no).** Stage 4 P4: `"May fail"` (predictions_v11.md:73); README: `"the study had expected it might fail"` (README.md:237). Stage 5 P1: `"May fail: by the estimates above the hot spot stays below 255.7 C, or, if the line of contact rises further, reaches it within the first minute"` (predictions_v12.md:46). Both branches of that reasoning are failures. README: `"The study had expected that it might fail"` (README.md:324). Stage 5 P6: `"May fail low: the model lacks the vent, ejecta and flame heat, and the estimates above fall short of 255.7 C at the central contact"` (predictions_v12.md:51); README: `"The study had expected that it might fail low"` (README.md:329).
5. **Stage 5 P3, P5 and P7 (marked no).** Their expectations are conditional holds: `"held if propagation occurs"` (line 48), `"Held if both propagate"` (line 50) and `"Held if enough runs propagate to give both spreads"` (line 52). Nothing propagated, and the scoring rule says `"A prediction about a propagation time or a mid-surface value is not met in a run without propagation."` (predictions_v12.md:40). P4's expectation was "Uncertain". The README and the note call all four "not met", never foreseeable.
6. **Stage 10 P2 (marked no).** The file named its condition, `"So P2 holds if, and only if, the short reading's root mean square at its better end exceeds 37.2 K, and P1 needs that end below 25 K, well under every reading the records hold."` (predictions_stage10.md:17), but it leaned toward P2 holding, not failing. The README counts only P3 and P5: `"Two verdicts were foreseeable when the predictions were written"` (README.md:670).
7. **Stage 2 P5(b) (marked no).** The file says `"the resolved half is about even odds"` (predictions.md:29).
8. **Stage 11 P4 (verdict pending, foreseen left empty).** The file already states the failure: `"P4 is already fixed by Stage 7's records."` and `"fails before any Stage 11 run (D111 (4))"` (predictions_stage11.md:16). The scorecard added in 0528d8b records P4 as failed, which on this table's rule is a foreseen failure. Stage 11 P5 carries a conditional one, and that scorecard also records P5 as failed; whether it failed on this condition is not checked here: `"If it stays 0 under every draw of both kinds, both its bands are zero, the thermal one is not narrower, and P5 fails on that test."` (predictions_stage11.md:18).
9. **Expectation column, Stages 1 to 3.** These files record central estimates, not likelihoods, so central estimates are given where the file states one. "none recorded" is used for Stage 1 P2 and P4 and for Stage 2 P5(c). P5(c)'s text does hold estimates, `"the hottest region peaks about 2 K above its passive 236.7 C, the lumped cell a few kelvin above its passive 152.8 C"` (predictions.md:30), which the README calls `"central estimates about 2 K and a few kelvin"` (README.md:96), but the file does not label them as such. Stage 2 P5(a) held `"Held, against the registered expectation"` (README.md:94).
10. **Expectation column, Stages 10 and 11.** These files give only the brief's expectation. The study's own pre-run readings are in their "What was known" sections and feed the foreseen column. For example, Stage 10 P5's expectation is `"Expectation: likely."` (predictions_stage10.md:34), yet the file foresaw its failure on a condition (line 19).
11. **Wording clash in Stage 10 P6 and P7.** "C1" and "C2" there name Parts C1 (held out) and C2 (ranking), not criteria: `"no permutation p-value in C1 lies below 0.05"` (line 35) and `"No model quantity in C2 correlates with the measured outcome or time"` (line 36). The CSV statements are reworded to avoid the clash.
12. **Stage 3 P2 central estimate.** `results/stage3_scorecard.json` gives the study's estimate as 9.2 and 64.2 s, where the predictions file says `"9.2 s and 64 s"` (predictions_stage3.md:26). The CSV follows the predictions file.
13. **Stage 8 verdicts.** These are not in `results/stage8_scorecard.json`, which holds only Part C's scorecards at the common fractions. They are in `results/stage8_verdicts.json` (`"holds"` per prediction) and agree with the README.
14. **Style choices in the statement column.** Test identifiers (M50_PT_Exp4 and so on) are kept as names. "Time-matching fraction" stands for f_t, the delivered fraction at which a criterion is met at the measured time. "Peak-matching fraction" stands for f_max, the fraction at which the thermocouple node peaks at the measured maximum. SEI is written out as solid electrolyte interphase. The expectation and quote columns copy the files' own wording, abbreviations included.
